| เกณฑ์ | สิ่งที่เราโชว์ |
|---|---|
| Impact 30% | เปลี่ยนการเล่นโซเชียลจาก "ไถแล้วกด Like" เป็น "สร้างต่อ" คนที่ไม่รู้ว่า GenAI ทำอะไรได้ก็เริ่มได้จากการกดการ์ดใบเดียว และของที่สร้างแชร์ต่อได้จนเกิด remix chain |
| Meta tools 25% | Muse Spark 1.3 ทำงานหลักทุกขั้น ได้แก่ ดูรูป เสนอไอเดีย เขียน spec เขียนแอป และสั่งแก้ ส่วน Muse Image ใช้ทำภาพ (P1) และ SAM 3.1 ใช้ตัดภาพ (stretch) ฟุตเทจสุดท้ายรันบน Meta Model API ตรง |
| Technical depth 20% | AI สร้างของที่รันได้จริงแบบไม่พัง (template + strict schema), โค้ดที่ AI เขียนรันใน sandbox มี smoke test และซ่อมเอง 1 รอบ, สลับผู้ให้บริการโมเดลได้ด้วย env, overlay บน FB ที่ทนต่อ DOM ของ FB, ลิงก์แชร์มีการ์ด OG |
| Demo 25% | flow ต่อเนื่องบนหน้า Facebook จริงตั้งแต่โพสต์จนถึงลิงก์ที่เพื่อนเปิดบนมือถือ |

**ทีม** (บทบาทให้ทีมเติมให้ตรง)
- **โอม** — เขียน extension และระบบ ทำวิดีโอ ดูแล repo
- **พี่เบิร์ด** — เสนอให้สร้างได้มากกว่าเกม (แยกเป็น 2 prompt), เสนอทางสำรองให้อ่านโพสต์จากหน้าเว็บ, เสนอให้หาเคสแอปจากคำบ่นใน X
- **พี่ชิน** — ทำสไลด์ cinematic 5 หน้า (มาจากตรงนี้ที่ใช้ Everest → snowboard เป็น hero), เสนอแนวคิด "รูป → อะไรก็ได้" (วิวฟูจิ → ชงชา/เล่นสกี) และหน้า HTML ไฟล์เดียวแบบ artifact
- **พิว** — presentation และวิดีโอ (ว่างวันอาทิตย์)
- **พี่ใน Discord (1 พ.ย.)** — เสนอขั้น "ชวนสร้าง" ให้ AI แนะนำสิ่งที่ทำได้จากโพสต์ เพราะผู้ใช้ส่วนใหญ่ไม่รู้ขีดความสามารถของ GenAI

**เส้นทางของไอเดีย:** ทีมเทียบ 2 ไอเดียคือ Farm Sim (AI วางผังฟาร์มและทำ feasibility) กับ VibeBook แล้วโหวตเลือก VibeBook เพราะเหมาะกับการพรีเซนต์และไวรัลกว่า ข้อกังวลตั้งแต่แรกคือคอนเซ็ปต์อธิบายยาก ต้องใช้วิดีโอช่วย

## 3. ปัญหาและโอกาส

ทุกข้อในส่วนนี้เป็นสมมติฐานของทีม ยังไม่มีผลทดสอบกับผู้ใช้จริง

**ปัญหา**
1. **โซเชียลเป็นแบบรับอย่างเดียว:** เห็นของเจ๋ง ๆ แล้วทำได้แค่ Like, Share หรือ Comment แรงบันดาลใจจบอยู่ตรงนั้น
2. **คนไม่รู้ว่า GenAI ทำอะไรได้:** พี่ในทีมเห็นจากประสบการณ์ว่าผู้ใช้ส่วนใหญ่ไม่เข้าใจขีดความสามารถของ GenAI การให้ตัวเลือกง่าย ๆ ช่วยให้เริ่มคลิกแรกได้
3. **เครื่องมือสร้างเริ่มจากช่องว่าง:** app builder และเครื่องมือ AI ส่วนใหญ่ให้เริ่มจากการพิมพ์ prompt หรือเขียน spec เอง แยกจากที่ที่เจอแรงบันดาลใจ
4. **ของที่สร้างไม่ได้เดินทางต่อ:** ผลงาน AI ส่วนใหญ่จบที่ไฟล์หรือภาพ ไม่มีทางให้คนถัดไปต่อยอดพร้อมเครดิตคนต้นทาง

**กลุ่มผู้ใช้ (จาก Handoff PDF, เป็นข้อเสนอ)**

| กลุ่ม | อยากได้อะไร |
|---|---|
| Curious scrollers | เห็นอะไรเจ๋งแล้วอยากมีเวอร์ชันของตัวเองในไม่กี่ขั้น |
| Casual creators | สร้างวิดีโอ เกม meme แอป โดยไม่ต้องเขียนโค้ดหรือ prompt ยาก ๆ |
| AI-showcase creators | ให้คนดูต่อยอดไอเดียได้ พร้อมเครดิตต้นทาง |
| Social communities | สร้าง challenge และ remix chain รอบเรื่องเดียวกัน |

**ทำไม Meta น่าจะสนใจ (สมมติฐาน)**
- ทำให้เกิดการสร้างบนแพลตฟอร์มมากขึ้น ไม่ใช่แค่การดู
- เป็นที่โชว์ว่า Muse ทำอะไรได้ ในบริบทที่คนใช้อยู่ทุกวันคือฟีดโซเชียล
- ลิงก์ที่แชร์และ remix ต่อกันเป็นวงจรที่พาคนกลับมาที่ฟีด

**ตัวชี้วัดที่ควรวัดในอนาคต (ยังไม่มีข้อมูล):** post impression → กด Vibe → สร้างสำเร็จ → แชร์ → มีคนเปิด → เกิด remix รุ่นที่สอง ถ้าเกมเล่นได้แต่ไม่มีใครแชร์ แปลว่าฝั่ง engineering ผ่านแต่สมมติฐานด้าน growth ยังไม่ผ่าน ต้องวัดแยกกัน

## 4. ประสบการณ์ผู้ใช้

**หลักของ release:** "See → Vibe → Experience → Share → Remix"

**หลักการออกแบบ (จาก Handoff PDF)**
- **Inspiration-first:** เริ่มจากโพสต์ที่ผู้ใช้เห็นจริง
- **Cross-modal:** สิ่งที่ได้ไม่จำเป็นต้องเป็นสื่อแบบเดียวกับต้นทาง เช่น รูป → เกม หรือรูป → แอป
- **Low friction:** ปุ่มเดียว + การ์ดแนะนำ ไม่โชว์เครื่องมือ developer
- **Play before code:** ได้เล่นหรือใช้ก่อน ค่อยสั่งแก้
- **Born to share:** มีลิงก์ เครดิตต้นทาง และ remix
- **Respect rights:** ตีความใหม่เป็นงานต้นฉบับ ไม่ก๊อป asset, เครื่องหมายการค้า หรือเนื้อหาส่วนตัว

**Flow เดโม 7 ขั้น**

| # | ขั้น | ผู้ใช้เห็นอะไร | ระบบทำอะไร |
|---|---|---|---|
| 1 | HOOK | ฟีด Facebook จริง มีโพสต์รูป Everest ของบัญชีทีม | – |
| 2 | MAGIC BUTTON | ชิป ✦ Vibe ที่มุมรูป กดแล้วหน้าต่าง VibeBook เลื่อนออกมาทางขวาของหน้า FB | extension อ่านรูป, caption และลิงก์ของโพสต์ที่กด |
| 3 | TRANSFORM | "Reading the photo…" → การ์ด 3 ใบที่ชวนสร้างคนละแบบ → กดเลือก → "Building… ✓ Spec valid ✓ Game loaded" | Muse ดูรูปแล้วเสนอการ์ด แล้วสร้างตามการ์ดที่เลือก |
| 4 | INTERACT | เล่นเกม: ซ้าย/ขวา หลบสิ่งกีดขวาง เก็บดาว คะแนนขึ้น หรือใช้แอปที่ AI เขียน | เกม/แอปส่งสัญญาณว่าโหลดสำเร็จ |
| 5 | PERSONALIZE | พิมพ์ "add a rocket boost and make it night" → เกมรีโหลด มีชิปบอกสิ่งที่เปลี่ยน (+ boost · night) | Muse แปลงคำสั่งเป็น spec ใหม่ แล้วเก็บเป็น version ใหม่ |
| 6 | SHARE | กด Share → ได้ลิงก์ → วางในโพสต์ FB ใหม่ → FB โชว์การ์ดภาพ "▶ Play Everest Rush" | publish หน้า `/p/:id` ที่มีการ์ด OG |
| 7 | REMIX | อีกคนเปิดลิงก์บนมือถือ → เล่น → กด ✦ Remix → พิมพ์ "neon night run" → ได้ลิงก์ใหม่ มีบรรทัด "remixed from Everest Rush by …" | fork เป็นของใหม่ที่ชี้กลับไปหาต้นทาง |

ข้อ 6–7 เป็นหน้าเว็บธรรมดา คนที่ได้ลิงก์ไม่ต้องลง extension

**ตัวอย่างคำพูดของผู้ใช้:** "Turn this into a snowboarding game." · "Make it faster, add rocket boost and mountain checkpoints." · "Share this game with my friends." · "Remix this into a night-mode challenge."

### 5.2 รายละเอียดทีละ feature

**F1 · ชิป ✦ Vibe บนรูป** 🧪
- ทำอะไร: เติมปุ่มเล็ก "✦ Vibe" ที่มุมขวาบนของรูปในโพสต์ Facebook ทั้งในฟีดและหน้าดูรูป
- ทำงานอย่างไร
  - หารูปที่มาจาก `fbcdn.net` ที่ส่วนที่มองเห็นได้กว้างอย่างน้อย 220×160 px ทำให้รูปโปรไฟล์และสตอรี่ไม่มีชิป
  - รูปที่ถูก crop ใน grid ก็มีชิปที่มุมของช่องที่มองเห็น
  - ถ้ามีอะไรนอกโพสต์บังรูปอยู่ เช่น dialog ชิปจะหายเอง
  - ชิปอยู่ใน shadow DOM นอก React ของ FB ทำให้ CSS ของ FB ไม่ทับ และชิปไม่หายเวลา FB วาดหน้าใหม่
- ทดสอบแล้ว: บนหน้า feed จำลองที่มีโพสต์รูปเดี่ยว โพสต์ 2 รูป โพสต์ข้อความล้วน และ dialog บัง ผ่านทุกกรณี ไม่มี error ใน console
- ยังไม่ได้ทดสอบ: บน Facebook จริง (selector ของ FB, CSP ของ FB, การดึงรูปจาก fbcdn)

**F2 · หน้าต่าง VibeBook (overlay)** 🧪
- หน้าต่างกว้าง ~440 px สูงเต็มจอ เลื่อนออกมาทางขวาของหน้า FB โดยหน้า FB ยังอยู่ข้างหลัง
- เป็นหน้าของ extension ที่ฝังด้วย iframe ทำให้ CSP ของ FB ไม่บล็อก และ FB อ่านข้อมูลข้างในไม่ได้
- ปิดด้วย ✕ หรือ Esc
- ธีมสีเข้มเกือบดำและม่วง ให้เข้ากับสไลด์

**F3 · อ่านโพสต์** 🧪
- อ่านรูป, caption (ตัดเหลือ 500 ตัวอักษร) และลิงก์ถาวรของโพสต์ โดยตัดพารามิเตอร์ติดตามของ FB (`__cft__`, `__tn__`) ออก
- ย่อรูปเหลือด้านยาว 1280 px แบบ JPEG ก่อนส่งให้ AI ให้ request เล็ก (รูปทดสอบได้ ~37 KB)
- อ่านเฉพาะโพสต์ที่ผู้ใช้กดเอง ไม่เก็บอะไรถ้าไม่กดสร้าง

**F4 · ทางสำรอง: ปุ่ม toolbar** 🧪
- ถ้าชิปบนรูปใช้ไม่ได้ ให้กดไอคอน VibeBook บนแถบเครื่องมือของ Chrome
- extension จะเลือกรูปที่กินพื้นที่บนจอมากที่สุด ถ้าเป็นโพสต์ข้อความล้วนจะใช้โพสต์ที่อยู่กลางจอ แล้วเปิดหน้าต่างเดียวกัน
- ส่งให้ AI เฉพาะข้อความกับรูป ไม่ส่ง HTML ทั้งหน้า เพราะหน้า FB หนักหลาย MB (ตรงกับไอเดียพี่เบิร์ดที่ให้ AI อ่านหน้าเว็บ)
- ทำงานเฉพาะบน facebook.com

**F5 · หน้า `/app`** 📋
- หน้าเว็บบนโดเมนของเรา อัปโหลดรูปหรือวางข้อความโพสต์ แล้วใช้ flow เดียวกับหน้าต่างใน extension
- ใช้ได้ 2 ทาง: เป็นทางสำรองสุดท้ายถ้า FB บล็อก และให้กรรมการลองได้โดยไม่ต้องติดตั้งอะไร
- เป็นการตีความแบบที่ 1 ของคำขอ "หน้าเว็บ HTML ไฟล์เดียวแบบ artifact" ของพี่ชิน (ยังไม่ได้ยืนยันกับพี่ชิน)

**F6 · ขั้นชวนสร้าง (การ์ด 3 ใบ)** 📋
- Muse Spark ดูรูปกับ caption แล้วตอบคำอธิบายฉาก อารมณ์ และการ์ด 3 ใบ แต่ละใบมีประเภท (`kind`), ชื่อ และคำชวนหนึ่งประโยค
- กฎของการ์ด
  - **ประโยคเดียว:** บอกผลลัพธ์ชัด ๆ เฉพาะกับโพสต์นั้น และพูดถึงตัวผู้ใช้ เช่น "you and your friend…" ไม่ใช่ชื่อแนวคิดลอย ๆ
  - **เสนอเฉพาะที่สร้างได้จริง:** ประเภทที่ให้ AI เลือกมาจากรายการที่เปิดใช้ในโค้ด ตอนนี้มี `game` กับ `app` จะเพิ่ม `image` เมื่อ F15 เสร็จ
  - **หลายแบบ:** การ์ด 3 ใบต้องมีมากกว่าหนึ่งประเภท
  - **การ์ดเกม:** ต้องเป็นเกมเดียวกันคนละธีมหรือกติกา เพราะมี template เกมเดียว
- เหตุผล: ผู้ใช้ไม่ต้องรู้ว่า AI ทำอะไรได้ แค่เลือกการ์ด ตรงกับข้อเสนอของพี่ใน Discord
- ตัวอย่างการ์ดอยู่ในส่วน 6

**F7 · Track เกม** 📋
- AI ไม่เขียนโค้ดเกมเอง แต่เลือกค่าใน **ExperienceSpec** (JSON ที่ทุกช่องเป็นตัวเลือกจำกัด) แล้วให้เกม template ที่เราเขียนเองอ่าน spec ไปเล่น ทำให้เกมเล่นได้ทุกครั้ง
- ตัวเกม
  - Phaser 3 แบบ downhill runner 2D
  - ใช้รูปจากโพสต์เป็นฉากหลังตรง ๆ ("รูปกลายเป็นเกม")
  - ตัวละครและสิ่งกีดขวางเป็น emoji (🏂 🌲 🪨 ⭐) จึงใช้ได้ทุกธีมโดยไม่ต้องวาด asset
- เล่นได้ทั้งคีย์บอร์ดและนิ้วบนมือถือ รวมถึงในเบราว์เซอร์ในแอป FB
- โหลดเสร็จแล้วส่งสัญญาณ `vibebook:ready` หน้าต่างจึงขึ้น "✓ Game loaded" จากการเช็กจริง ไม่ได้แต่งขึ้น
- รายละเอียด spec อยู่ในส่วน 8.5

**F8 · Track แอป** 📋
- AI เขียนหน้า HTML ไฟล์เดียว (CSS/JS อยู่ในไฟล์ ใช้รูปจากโพสต์ได้ ห้ามเรียก network ภายนอก)
- แสดงใน iframe แบบ sandbox (`srcdoc` + `sandbox="allow-scripts"`) ทำให้ origin แยกจากเว็บเรา โค้ดที่ AI เขียนแตะ token หรือข้อมูลของหน้าเราไม่ได้
- **Smoke test:** รอสัญญาณ `vibebook:ready` ภายใน ~5 วินาที ถ้าไม่มาหรือมี error จะส่ง error กลับให้ AI ซ่อม 1 รอบ
- ขั้นเขียนโค้ดแยกโมเดลได้ใน env (`*_CODE_MODEL`) ถ้า Muse contributor เขียนโค้ดไม่ดีพอ เปลี่ยนเฉพาะขั้นนี้ได้โดยไม่กระทบขั้นอื่น
- เป็นการตีความแบบที่ 2 ของคำขอพี่ชิน (ผลลัพธ์เป็นหน้า HTML แสดงในหน้าต่างแบบ artifact)
- ในวิดีโอใช้เคสแอปที่สร้างไว้ล่วงหน้าด้วยระบบเดียวกัน และบอกในวิดีโอตรง ๆ

**F9 · สั่งแก้ด้วยภาษาธรรมชาติ** 📋
- พิมพ์ เช่น "add a rocket boost and make it night" แล้ว AI จะเปลี่ยนเฉพาะช่องที่เกี่ยวใน spec และเก็บเป็น version ใหม่
- โชว์ชิปบอกว่าเปลี่ยนอะไร (+ boost · night) และถ้าขอสิ่งที่ template ทำไม่ได้ จะบอกตรง ๆ ว่าทำไม่ได้
- ผลแน่นอนเพราะเปลี่ยนได้แค่ค่าที่ template รองรับ

**F10 · Publish + การ์ดลิงก์บน FB** 📋
- กด Share แล้วได้ลิงก์ `/p/:id`
- หน้านี้มี OG tags ทำให้ FB โชว์การ์ดลิงก์ที่มีรูปต้นทาง ชื่อเกม และปุ่ม ▶ (ภาพการ์ดสร้างด้วย `next/og`)
- ต้องทดสอบด้วย FB Sharing Debugger และเปิดผ่านเบราว์เซอร์ในแอป FB บนมือถือ
- ใช้ production URL เพราะ URL preview ของ Vercel อาจตอบ 401 ให้ crawler ของ FB

**F11 · Remix + เครดิต** 📋
- คนที่ได้ลิงก์กด ✦ Remix แล้วพิมพ์สิ่งที่อยากเปลี่ยน จะได้ของใหม่ที่ชี้กลับไปหาต้นทาง พร้อมบรรทัด "remixed from … by …"
- ทำบนเว็บธรรมดา ไม่ต้องลง extension
- แก้ของคนอื่นไม่ได้ ทำได้แค่ remix เป็นของใหม่

**F12 · Behind the scenes** 📋
- ทุก experience เก็บ `trace` ว่าแต่ละขั้นใช้โมเดลไหน ใช้เวลากี่ ms และผ่านหรือไม่
- ใช้โชว์ในเดโมช่วง TRANSFORM และใช้ตอบคำถามเรื่องการใช้ Meta tools

**F13 · กันคนนอกยิง API** 📋
- ตอนสร้างจะได้ `editToken` กลับมา การแก้และ publish ต้องส่ง token นี้ server เก็บแค่ค่า hash
- จำกัดจำนวนครั้งต่อ IP บนขั้นที่เรียก AI ด้วย `@upstash/ratelimit`
- ID สุ่ม 10 ตัวอักษรเดาไม่ได้ draft จึงไม่โผล่ที่ไหน ส่วนหน้า `/p/:id` แสดงเฉพาะของที่ publish แล้ว

**F14 · สลับผู้ให้บริการโมเดล** 📋 (ไฟล์ env พร้อมแล้ว)
- ตั้ง `AI_PROVIDER=openrouter | meta` ตัวเดียว โค้ดจะเลือก base URL, key และโมเดลของเจ้านั้น
- ส่วนภาพแยกเป็น `IMAGE_PROVIDER` เพราะ Muse Image มีเฉพาะบน Meta ตรง
- ตอนนี้ใช้ OpenRouter เพราะ Meta ยังไม่มีเครดิต และจะสลับไป Meta ก่อนอัดฟุตเทจสุดท้าย

**F15 · ภาพ "ใส่ตัวคุณเข้าไปในฉาก"** ➕
- รูปโพสต์ + เซลฟี่ของผู้ใช้ (ไม่บังคับ) → แก้ภาพด้วย Gemini image ผ่าน OpenRouter (~$0.04/ภาพ) หรือ Muse Image บน Meta ($0.01/ภาพ)
- ภาพที่ได้ใช้เป็นการ์ด OG ตอนแชร์ได้เลย และใช้ adapter เดียวกันวาดฉากใหม่ตอน remix ได้ (เช่น neon night)
- มาจากตัวอย่างของพี่ใน Discord: "ภาพเซลฟี่ผมกับแฟนกำลังขับเรือหนีตำรวจน้ำ"
- เดโมใช้เซลฟี่ของคนในทีมที่ยินยอมเท่านั้น

**F16–F21** เป็น P1 ตามตารางด้านบน ทำตามลำดับถ้ามีเวลา SAM 3.1 ใช้ได้เฉพาะบน Meta API

**F22 · วิดีโอ** ⛔
- Meta Model API ไม่มีโมเดลสร้างวิดีโอ
- OpenRouter มี API วิดีโอ (ใช้รูปโพสต์เป็นเฟรมแรกได้) แต่ต้องรอ 30 วินาทีถึงหลายนาที คิดเงินเป็นวินาที และไม่ได้คะแนน Meta tools
- เก็บไว้เล่าเป็น future (หมวด Watchable)

## 8. สถาปัตยกรรมและเทคนิค

### 8.1 ภาพรวม

```
facebook.com ──(content script)── ชิป ✦ Vibe
      │ คลิก
      ▼
<iframe chrome-extension://…/panel.html>   ← หน้าต่างทับหน้า FB (CSP ของ FB ไม่บล็อก)
      │ ดึงรูปจาก fbcdn → ย่อ 1280px → base64
      ▼
Next.js บน Vercel ─ /api/vibe  /api/experiences/*  ─→ lib/ai.ts ─→ OpenRouter | Meta Model API
      │                                        └→ lib/store.ts ─→ Upstash Redis (JSON) + Vercel Blob (รูป)
      ▼
/play/:id?embed=1  (เกม Phaser หรือแอป HTML)  ← ฝังในหน้าต่าง และในหน้า /p/:id
/p/:id             (OG tags + ปุ่ม Remix)       ← ลิงก์ที่แชร์ลง FB
/app               (ใช้ได้โดยไม่ต้องลง extension)
```

### 8.2 Stack

| ส่วน | ใช้อะไร | เหตุผล |
|---|---|---|
| Extension | Chrome Manifest V3, JavaScript ล้วน ไม่มี build step | เล็ก แก้แล้วโหลดใหม่ได้ทันที |
| Server | Next.js (TypeScript) บน Vercel | API กับหน้าเว็บอยู่ที่เดียว deploy ง่าย |
| เกม | Phaser 3 | เกม 2D บนเบราว์เซอร์ เล่นบนมือถือได้ |
| ข้อมูล | Upstash Redis (JSON) | อ่านแล้วได้ค่าล่าสุดทันทีหลังสั่งแก้ |
| รูป | Vercel Blob | เขียนครั้งเดียวต่อ experience |
| ตรวจข้อมูล | zod + JSON Schema แบบ strict | ผลจาก AI ต้องผ่าน schema ก่อนใช้ |
| AI client | OpenAI SDK ตัวเดียวสำหรับทั้ง OpenRouter และ Meta | ทั้งสองเจ้าใช้รูปแบบ API แบบ OpenAI |

### 8.3 Extension (โค้ดจริงใน `extension/`)

| ไฟล์ | หน้าที่ |
|---|---|
| `manifest.json` | สิทธิ์: `storage`, `activeTab`, `scripting` · host: facebook.com, fbcdn.net, localhost:3000, *.vercel.app · เปิดให้ FB ฝังได้แค่ `panel.html` |
| `content.js` | หารูปโพสต์ วางชิป เปิด/ปิดหน้าต่าง อ่านโพสต์ (ทั้งแบบกดชิปและแบบกลางจอ) |
| `background.js` | ทางสำรองปุ่ม toolbar: ส่งคำสั่งให้ content script หรือ inject เข้าไปถ้ายังไม่มี |
| `panel.html/.js/.css` | หน้าต่าง VibeBook: ดึงและย่อรูป แสดงขั้นตอน (ขั้นถัดไปคือต่อเข้า `/api/vibe`) |

**selector ที่ใช้หาโพสต์บน FB:** `[role="article"]`, `[aria-posinset]`, `[role="dialog"]`, `[data-pagelet^="FeedUnit"]` และหา caption จาก `[data-ad-preview="message"]` / `[data-ad-comet-preview="message"]` ถ้าไม่เจอจะใช้ข้อความทั้งโพสต์

### 8.4 Server API

| Method | Path | รับ | ตอบ |
|---|---|---|---|
| POST | `/api/vibe` | `{image (base64, ไม่บังคับ), caption, postUrl, platform}` | `{scene:{description, mood}, suggestions:[{kind, title, pitch}×3]}` |
| POST | `/api/experiences` | `{image, source, suggestion, creatorName}` | `{id, kind}` สร้าง spec (เกม) หรือ HTML (แอป) แล้วเก็บเป็น draft |
| GET | `/api/experiences/:id` | – | experience เต็ม |
| POST | `/api/experiences/:id/edit` | `{instruction}` | `{spec, changeSummary[], unsupported?}` + version ใหม่ |
| POST | `/api/experiences/:id/publish` | – | `{url: /p/:id}` |
| POST | `/api/experiences/:id/remix` | `{instruction, creatorName}` | `{id, url}` ของใหม่ที่มี `parentId` |

หน้าเว็บ: `/play/:id` (เต็มจอ เล่นได้ทั้งคีย์บอร์ดและนิ้ว) · `/p/:id` (การ์ด OG + เกม + ปุ่ม Remix + เครดิต) · `/api/og/:id` (ภาพการ์ด) · `/app`

**ข้อมูลที่เก็บต่อ experience** (key `exp:{id}`)
`{id, parentId, version, versions[], kind, spec | html, imageUrl, source:{platform, postUrl, captionExcerpt}, creatorName, editTokenHash, published, createdAt, trace:[{step, model, ms, ok}]}`

### 8.5 ExperienceSpec v0.2 (ที่เกมอ่าน)

```json
{
  "title": "Everest Rush",
  "tagline": "Outrun the sunrise down the roof of the world",
  "player": "🏂",
  "obstacles": ["🪨", "🌲", "🚩"],
  "collectible": "⭐",
  "timeOfDay": "sunset",
  "speed": "fast",
  "density": "medium",
  "powerups": ["boost"],
  "goal": { "type": "distance", "target": 2000 },
  "scoreLabel": "meters"
}
```

| ช่อง | ค่าที่ใช้ได้ |
|---|---|
| `player` | 🏂 ⛷️ 🛷 🏄 🛹 🚵 |
| `obstacles` | 1–3 ตัวจากรายการ ~20 emoji (🪨 🌲 🚩 ⛄ 🧊 🐧 🌵 🪵 🚧 🐻 …) |
| `collectible` | ⭐ 💎 🪙 ❄️ 🍀 |
| `timeOfDay` | day · sunset · night · neon (ใส่ tint ทับรูป) |
| `speed` | chill · normal · fast · insane |
| `density` | low · medium · high |
| `powerups` | 0–3 จาก boost · shield · magnet |
| `goal.type` | distance · score · survive |

ทุกช่องเป็นตัวเลือกที่ template รองรับจริง AI จึงเลือกนอกกรอบไม่ได้ และการสั่งแก้ให้ผลแน่นอน

### 8.6 ขั้นตอนของ AI

| ขั้น | โมเดล | รับ | ให้ผล |
|---|---|---|---|
| Prompt 1: ชวนสร้าง | Muse Spark 1.3 | รูป + caption | ฉาก + อารมณ์ + การ์ด 3 ใบ |
| Prompt 2: สร้าง (เกม) | Muse Spark 1.3 | การ์ดที่เลือก + รูป | ExperienceSpec |
| Prompt 2: สร้าง (แอป) | Muse Spark 1.3 หรือ `*_CODE_MODEL` | การ์ดที่เลือก + รูป | HTML ไฟล์เดียว |
| สั่งแก้ | Muse Spark 1.3 | spec เดิม + คำสั่ง | spec ใหม่ + สรุปสิ่งที่เปลี่ยน |
| Remix | Muse Spark 1.3 | spec ต้นทาง + คำสั่ง | spec ใหม่ (ของใหม่) |
| ภาพ (P1) | Muse Image 1.0 หรือ Gemini image | รูปโพสต์ (+ เซลฟี่) + prompt | ภาพใหม่ |

**กฎการใช้ AI**
- **แยก 2 prompt:** ช่วยเลี่ยงข้อจำกัดของ schema แบบ strict ของ Meta ที่ห้ามใช้ `oneOf` และทำให้การ์ดขึ้นเร็ว
- **schema แบบ strict:** ใช้ `response_format: json_schema` โดย `additionalProperties: false` ทุกช่องอยู่ใน `required` ไม่ใส่ `min`/`max` ใน schema แล้วไปบังคับด้วย zod แทน ถ้าไม่ผ่านให้ AI ซ่อม 1 รอบ
- **OpenRouter:** ส่ง `provider: {require_parameters: true}` ไม่งั้นถ้าเจ้าปลายทางไม่รองรับ schema จะถูกทิ้งเงียบ ๆ
- **ล็อก model ID แบบเต็ม:** ไม่ใช้ alias แบบ `-latest`
- **เนื้อหาโพสต์เป็นข้อมูล ไม่ใช่คำสั่ง:** caption และคอมเมนต์ถูกห่อด้วย delimiter และ system prompt สั่งห้ามทำตาม ส่วนข้อความที่ AI แต่ง (ชื่อ, tagline) จำกัดความยาวและแสดงเป็น text เท่านั้น

### 8.7 จุดที่โชว์ Technical depth ได้

สถานะ: ข้อ 5 เขียนแล้ว (🧪) ข้ออื่นยังเป็นแผน (📋) ห้ามขึ้นสไลด์ว่าทำแล้วจนกว่าจะเสร็จ

1. **AI สร้างของที่รันได้จริงทุกครั้ง:** เกมใช้ template + spec ที่เป็นตัวเลือกจำกัด ตรงกับ risk register ใน PDF ("templates + strict specs + smoke tests")
2. **โค้ดที่ AI เขียนรันอย่างปลอดภัย:** iframe sandbox แยก origin, smoke test ด้วยสัญญาณ `vibebook:ready` และซ่อมเองจาก error จริง 1 รอบ
3. **Schema เดียวใช้ได้ทั้ง OpenRouter และ Meta:** ออกแบบตามกฎ strict ของ Meta ตั้งแต่วันแรก สลับเจ้าแล้วไม่เจอ 400
4. **สลับผู้ให้บริการด้วย env ตัวเดียว** และแยกโมเดลตามขั้นได้ (chat, code, image)
5. **Overlay บน Facebook ที่ทน DOM ของ FB:** shadow DOM นอก React tree, ชิปลอยตามตำแหน่งรูป, คำนวณส่วนที่มองเห็นของรูปที่ถูก crop และซ่อนชิปเมื่อมี dialog บัง
6. **ลิงก์แชร์ที่เป็นของจริงบน FB:** การ์ด OG สร้างจากรูปต้นทาง เปิดได้ในเบราว์เซอร์ในแอป FB
7. **Trace ทุกขั้น:** รู้ว่าโมเดลไหนทำอะไร ใช้เวลาเท่าไร และผ่านไหม

## 11. ความปลอดภัย ความเป็นส่วนตัว และสิทธิ์

- **อ่านเฉพาะที่ผู้ใช้กด:** อ่านเฉพาะโพสต์ที่ผู้ใช้กดเองในเบราว์เซอร์ของตัวเอง ไม่ดึงข้อมูลเบื้องหลัง ไม่ใช้ Facebook Graph API และไม่เก็บอะไรถ้าไม่กดสร้าง
- **ส่งเฉพาะที่จำเป็น:** ส่งข้อความกับรูปของโพสต์นั้น ไม่ส่ง HTML ทั้งหน้า
- **Draft เป็นส่วนตัว:** ID เดาไม่ได้ จะเป็นสาธารณะเมื่อกด Share เท่านั้น
- **แก้ของคนอื่นไม่ได้:** ใช้ edit token คนอื่นทำได้แค่ remix เป็นของใหม่ที่มีเครดิตต้นทาง
- **โค้ดที่ AI เขียนรันใน sandbox:** origin แยก แตะ token หรือข้อมูลของเว็บเราไม่ได้
- **กัน prompt injection:** caption และคอมเมนต์ถือเป็นข้อมูล และผลลัพธ์ต้องผ่าน schema
- **โหมด contributor:** Meta เอา prompt และรูปไปเทรนได้ ตอนพัฒนาและเดโมจึงใช้รูปที่ทีมเป็นเจ้าของเท่านั้น ถ้าต้องใช้รูปคนอื่นให้สลับไป Muse ตัวเต็ม และเซลฟี่ต้องได้รับความยินยอม
- **ตีความใหม่ ไม่ก๊อป:** ไม่ก๊อปงานศิลป์ของตัวละคร โลโก้ เพลง ฟุตเทจ หรือโค้ดที่มีเจ้าของ
- **คำถามที่ยังเปิด (BD/Legal จาก PDF):**
  - เจ้าของโพสต์ปิดไม่ให้ remix ได้ไหม
  - ใครเป็นเจ้าของผลงานที่สร้าง
  - ขั้นตอนถอดเนื้อหาเป็นอย่างไร
  - จัดการรูปเด็กหรือโพสต์ส่วนตัวอย่างไร (ค่าเริ่มต้นควรเข้มไว้ก่อน)

## 13. ความเสี่ยงและทางสำรอง

| ความเสี่ยง | ทางสำรอง |
|---|---|
| หาโพสต์หรือรูปใน DOM ของ FB ไม่เจอ | ปุ่ม toolbar อ่านโพสต์กลางจอ → หน้า `/app` |
| AI เขียน HTML พังหรือช้า | smoke test + ซ่อม 1 รอบ · เปลี่ยน `*_CODE_MODEL` · เคสเดโมสร้างเก็บไว้ล่วงหน้า |
| Muse contributor ดูรูปแย่หรือ JSON พัง | zod + ซ่อม 1 รอบ แล้วลอง Muse ตัวเต็ม หรือ DeepSeek |
| เวลาเขียนโค้ดเกินเพดานของ Vercel Hobby | เช็ก `maxDuration` (เปิด Fluid Compute) ถ้าไม่พอให้ stream |
| FB cache การ์ดลิงก์เก่า | กด re-scrape ใน Sharing Debugger ก่อนอัด |
| key ของ Meta เรียกจากไทยไม่ได้ หรือเครดิตไม่มา | ใช้ Muse ผ่าน OpenRouter ซึ่งยังเป็นโมเดล Meta |
| emoji หน้าตาไม่เหมือนกันในแต่ละ OS | ยอมรับได้ในงานนี้ |

## 18. สิ่งที่พูดได้ และสิ่งที่ห้ามพูดเกินจริง

**พูดได้ (เมื่อทำเสร็จและทดสอบแล้ว)**
- กดปุ่มบนโพสต์ Facebook จริงแล้วได้เกมที่เล่นได้
- AI แนะนำสิ่งที่สร้างได้จากโพสต์ ทั้งเกมและแอป
- แชร์เป็นลิงก์ เพื่อนเปิดบนมือถือแล้ว remix ต่อได้พร้อมเครดิต
- ใช้โมเดลของ Meta ในทุกขั้นหลัก

**ห้ามพูดหรือต้องติดป้าย**
- ห้ามบอกว่าเชื่อมกับ Facebook อย่างเป็นทางการ เพราะเป็น browser extension prototype ไม่ใช่ปุ่มในแอป FB
- สไลด์ cinematic 5 หน้าเป็นภาพคอนเซ็ปต์ ไม่ใช่ screenshot ของจริง
- เคสที่สร้างไว้ล่วงหน้าต้องติดป้าย
- ยังไม่มีผลทดสอบกับผู้ใช้จริง ไม่มีตัวเลข conversion หรือ retention
- ตัวเลขเป้าหมายใน PDF (เช่น game load ≥ 70%, เข้าใจรูปถูก ≥ 85%) เป็นเป้า ไม่ใช่ผลที่วัดได้
- ไม่สัญญาภูมิประเทศ Everest ที่สมจริง ฟิสิกส์สกีที่แม่นยำ หรือการสร้างซ้ำเกมจากภาพเดียวได้ตรงต้นฉบับ
- ไม่มีการสร้างวิดีโอ
- อย่าอ้างว่าเป็น white space ที่ไม่มีใครทำ เพราะยังไม่ได้ audit คู่แข่งใหม่
